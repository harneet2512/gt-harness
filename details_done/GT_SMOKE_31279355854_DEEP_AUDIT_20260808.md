## Repository-intelligence failures

### `gpt2-codegolf`: no supported source

The source mirror contains zero indexable source files and two excluded
artifacts. The initial index is `no_supported_source` with zero nodes and
edges, so the graph gate cannot certify definitions/callers. The engine made
no repository claim and delivered no fabricated payload. This is a real
substrate/applicability limitation for this task, not a delivery-timing bug.
It was already reward 0 in GT-off.

### `write-compressor`: recovered graph incorrectly left treatment invalid

The task initially indexed `decomp.c` successfully (4 nodes, zero edges) and
ended with a healthy current graph (98 nodes, zero edges; source revision
matched; sensor healthy). At action 6 the sensor temporarily degraded. The
frontier receipt correctly recorded `substrate_failure` for those calls, then
later recorded `no_frontier` after recovery. The agent aggregates any
historical substrate failure into final `repository_intelligence.failures`,
so the final treatment is marked failed despite the final substrate being
healthy/current. This is the fixable bug.

The correct rule is: retain transient failures for observability, but the
promotion gate must evaluate the final current substrate and the latest
frontier state. A recovered transient must not invalidate a completed task.

## `schemelike-metacircular-eval` loss

The task had a valid graph (335 nodes / 254 edges), one grounded 133-character
payload, complete accounting, and no censor or exception. The first provider
request was not altered by a visible GT payload. The model nevertheless took
91 calls and hit the normal solve boundary with reward 0. This run alone does
not establish causality. It is a real outcome regression that requires the
archived request/trajectory diff and a separately authorized ablation before
any claim that GT caused or prevented it.

## Required next changes (before another paid smoke)

1. Change final repository-intelligence aggregation so a historical frontier
   `substrate_failure` is recorded as a transient event but only the final
   current evidence/frontier decision can fail the treatment gate. Preserve
   source-revision and stale-evidence failures as fail-closed when they remain
   current.
2. Add a regression test: healthy graph → one degraded frontier call → graph
   recovery/no-frontier must finish `repository_intelligence.status=passed` and
   retain a `transient_frontier_failure` receipt.
3. Add an explicit `not_applicable_no_supported_source` outcome class for
   source-less benchmark tasks. It must not fabricate graph evidence, but the
   benchmark report must distinguish it from an engine/index defect. Whether
   the promotion gate excludes such tasks must be decided explicitly, not by
   counting the task as a green treatment.
4. Run the provider-free census, readiness audit, pre-smoke gate, and archived
   trajectory replay after the patch. Do not start the 89-task run.
5. Only after those gates pass, run a separately authorized matched ten-task
   smoke and audit the scheme trajectory against GT-off/ablation. Treat the
   prior 8/10 result as rejected evidence.
