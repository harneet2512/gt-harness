## Root cause of the intelligence failure

`gpt2-codegolf` began with no supported source in the initial source-only
mirror. The model then created `gpt2.c`. The authoritative workspace sensor
detected the new C file and attempted to capture it with:

```text
python3 -c 'import base64,json,pathlib,sys; ...' gpt2.c
```

The task image does not contain `python3`; the host receipt records return code
`127` for every such capture. Since `after_contents['gpt2.c']` was therefore
missing, `RepositorySession.apply_transition()` fail-closed to
`mirror_incomplete`; no incremental index refresh was recorded. The final
receipt reports:

```text
status: failed
failures: mirror_incomplete, no_supported_source, graph_missing,
           graph_not_current, repository_intelligence_invalid,
           repository_refresh:no_supported_source, frontier:substrate_failure
graph nodes: 0, graph edges: 0
source mirror files: 0
```

This is a real architecture bug at the sensor-to-mirror boundary, not evidence
that C is unsupported (`language_registry.py` explicitly recognizes `.c`). The
engine correctly refused to fabricate graph facts, and the merge gate correctly
rejected the treatment. The next repair must provide a portable, deterministic
source-capture path that does not require Python in the task image, then prove
incremental mirror/index refresh provider-free before another paid smoke.
