## Defects fixed in `e41d1fe9`

### F9 — `refused_then_delivered` was phase-confused (false positive)

Journal is two-phase per decision: `delivery_prepared` (admission, seq 188) →
`delivery_refused` for rejected siblings (seq 190) → `evidence_delivery` /
`receipt` / `provider_delivery` (commit, seq 196–198). The validator compared the
refusal's sequence against the **commit** sequence — always later even for a
sibling admitted before the refusal fired. Iteration 7 carried twins: copy
`7e00709e` admitted ordinal 1, twin `bf65b6b5` refused `candidate_ordinal` 2
(`localization_fire_once` = "sibling already pending in this batch").

Fix in `gt_harness/runtime_receipts.py`:

- `delivery_ordinal` carried through `_delivery_rows` and
  `_provider_delivery_receipts`, emitted iff present on the source event
  (legacy HAR-81 journals lack it → recomputed legacy rows stay identical,
  preserving recorded-run census equality).
- `refused_then_delivered` now fires on the admission axis:
  same identity (any order), or same dedup key with
  `delivery_ordinal >= candidate_ordinal`.
- `refused_delivery_present` = refused identity delivered same iteration,
  identity match, any order.
- Issuance rejects refusal-bearing journals whose delivery rows lack
  `delivery_ordinal` — ambiguous evidence fails closed.
- Same predicate applied at the audit site; the audit recomputes all three row
  sets and demands exact list equality, so collector changes stay consistent.

### F10 — `_reward` written against an imagined pier shape

`standardize_benchmark_result.py` requires `aggregate_reward == trial_reward`.
Trial yielded 1.0 correctly, but pier's real aggregate shape is
`metrics: [{"mean": 1.0}]` + `reward_stats.reward: {"1.0": [trial]}` —
`_reward` read `metrics[*].reward` which never exists in production →
`aggregate_reward=None` → gate fails → `missing_verifier`. The test fixture used
`{"reward": 1.0}`, a shape real pier never emits. **Every solved run would have
reported `official_verifier_missing`.**

Fix: `_reward` accepts a single-key `reward_stats.reward` map as the aggregate
reward; multi-key maps (mixed outcomes) do not collapse; aggregate must equal
trial reward before `GRADED`; conflicts stay typed-ungraded. The attestation
path recomputes reward through the same imported functions, so one fix repairs
write and audit paths.

### F11 — monitor artifacts vanished silently

`run-status.md` was written to CWD — outside `results/swelive/` which is the
collected artifact tree — and `upload_transient_artifact.py` exits 0 on every
failure, so the designed every-2-min journal snapshots produced zero artifacts
for the whole run. Fix in `.github/workflows/swelive_gt_harness_paid.yaml`:
snapshots now write to `results/swelive/run-status/run-status-${RUN_ID}-${TASK}-${SEQ}.md`,
emit failures captured to `emit-errors.log`, upload failures to
`upload-errors.log`, all non-fatal (observability never alters benchmark outcome).
